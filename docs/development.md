# Development

## Package and generated source

The package uses Poetry metadata in `pyproject.toml` and the `poetry-core` build backend. It targets Python `^3.9` and depends on `httpx >=0.23,<0.29`, `attrs >=22.2`, and `python-dateutil ^2.8`. The modules under `rium_api_client/api/` and `rium_api_client/models/` are generated by `openapi-python-client`; avoid hand-editing generated files.

## Regenerate

The Docker development environment provides `openapi-python-client` 0.29.1 and mounts the schema and client source trees into its generator container. From that generator environment, run:

```sh
openapi-python-client generate \
  --path /app/schema/openapi.yaml \
  --output-path /app/rium-api-client/ \
  --overwrite
```

Generation overwrites generated files and may update package metadata. Review the full diff, including README and `pyproject.toml`, before accepting it. The generator input is the API schema version available in the development environment; the client does not embed an automatic link to a particular schema commit.

## Validation and packaging

Ruff is configured with line length 120 and rules `F`, `I`, and `UP`. Run `ruff check .` from the repository root when Ruff is available. No test suite or CI workflow is present in the checked-out repository, so generation and linting do not establish runtime compatibility with every server operation.

Build a source distribution and wheel with:

```sh
poetry build
```

The package is published on PyPI. `pyproject.toml` declares package metadata but does not configure a repository-specific publish target or release automation. Poetry publishes to PyPI by default, so an explicit repository URL is not required. Publishing credentials are supplied outside the project file, for example with `poetry config pypi-token.pypi <token>` or the `POETRY_PYPI_TOKEN_PYPI` environment variable. A typical manual release is `poetry publish --build`; verify the version and release process before publishing because package uploads are not reversible. For a private index, configure a named upload repository and its credentials separately.

## Contract maintenance

The generated operations reflect the schema used at generation time, which may not describe every route or server behavior. When a documented API contract changes, regenerate, review generated signatures and models, run Ruff, and test representative calls against an authorized non-production environment where available. No live API test environment is configured by this repository.
